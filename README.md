# pdf-to-database

把**表格型 PDF**（政府价格文件、公报、统计年鉴、连续出版物、批量报表）转成结构化数据库（JSON / SQLite / CSV）的工作流、坑位手册与工具箱。

## 为什么需要它

每个 PDF 源都有自己的版式，**通用解析器不存在**——大厂 OCR 产品也一样，它们处理不了"连续出版物每期版式还漂移"这类场景。真正吃时间的不是文本识别，而是版式适配的反复踩坑。

本项目把一次真实生产实践（青海《工程造价管理信息》双月刊 40 期 → 16.7 万条结构化数据，修复 10 个版式类 Bug）中积累的方法论固化下来：**流程标准化 + 高频陷阱内建 + 交付前体检**，让新源的适配从"踩坑几天"变成"按流程几小时"。

## 内容

```
SKILL.md                       六阶段工作流、四类防御、症状速查表
scripts/probe_tables.py        侦察探针：文本层检测 + 版式（列数）分组
scripts/extractor_skeleton.py  抽取骨架：四防御已内建
scripts/audit_template.py      体检模板：伪列共现 + 基线回归对比
references/case-qinghai.md     实战复盘：10 个 Bug 的症状 → 机制 → 修法
```

## 核心方法论

**六阶段**：侦察 → 逐版式写解析器（+ OCR 兜底）→ 后处理合并 → 全量抽取 → 体检交付 → 增量更新

**四类必防陷阱**（骨架中已实现，删掉就会中招）：

| 防御 | 症状 | 机制 |
|---|---|---|
| A 合并单元格继承 | 部分行县名/分组名为空 | 县名只在首列出现，需向后继承 |
| B 碎片行跳过 | 整页县名列全空，价格塌缩成伪列 | 竖排"单位"拆出的"单"字中断表头收集 |
| C 匿名价格列防线 | 一个"XX地区"伪列吞掉 6 个县的价格 | `area or default` 兜底 + 同槽位互相覆盖 |
| D 拼行双价拆分 | 数值错位成 `'350.0035'`/`'0'` | 同印刷行两价格词粘连，拆分正则贪婪回溯 |

## 关键认知（都是踩出来的）

- **反常数值先核对原件再判断**：C45 德令哈 510 > 乌兰 490 与相邻行规律相反，逐字比对后确认是原件本身如此 —— 保留，不要"顺手修正"。
- **原件会印错**：某县名在海西劳务表被系统性误印（机械表却是正确的），需 CountyFix 映射归一。
- **单地区统一价表是合法形态**：体检一刀切会把 284 处合法列报成伪列。真伪列判据是"地区列与县列**共存**"。
- **非标准文件名会漏抽**：政府站原始文件名（`P02026...pdf`）不被常规 glob 匹配，元数据需从正文回退解析。
- **体检不可省**：没有 baseline 对比与原件抽样的数据，不可信。

## 快速开始

```bash
pip install pymupdf          # 或 pip install --target vendor/ 随项目走

# 1. 侦察
python scripts/probe_tables.py your.pdf --sample 10

# 2. 改骨架适配版式（标了「按版式定制」的位置）
python scripts/extractor_skeleton.py your.pdf --out out.json

# 3. 交付前体检
python scripts/audit_template.py ./data --baseline ./data_prev
```

适用于 Claude Code / WorkBuddy 等支持 agent skills 的环境：将本目录放入 `~/.workbuddy/skills/` 即可。
